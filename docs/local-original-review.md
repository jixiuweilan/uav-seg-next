# 本地原图复核：组员操作说明

复核页面由负责人转交，共22条关系、35张去重原图。
大家各自已有完整官方数据，直接使用本地副本，不需要中心数据工作站。
本页替代当前任务中的旧“中文复核练习.html”；旧练习无需补做。

## 从打开到回传

1. 将负责人转交的 HTML 保存到电脑，用已有浏览器打开本地文件。
   顶部应显示“本地原图针对性复核”和22条、35张。
2. 点击“选择原图文件夹”，选择训练原图 PNG 所在目录，通常是 `train/images`。
   不要选择 `train/masks`。程序只读取本批35张图，其余文件只经过文件名筛选。
   浏览器的目录选择提示可能称作“上传”，本页面实际只在本机读取，不联网传图。
   不支持选目录时，可以在“补选原图文件”中多选 PNG。
3. 页面自动核对文件大小、SHA-256 和图像尺寸。不需手工比对、不需装 Python，
   也不重跑全量审计。看到“原图已核对35/35”即可顺序复核；只加载部分图也能
   处理已核对的图像对。缺图或哈希不一致会显示编号，反馈原提示即可，不改图片。
4. 填姓名。两图默认按100%原始像素显示，在各自图像区域滚动查看完整细节。
   可先用50%看全貌，再切回100%或200%检查固定地物。
5. 为每条选择确认、排除或存疑，写明地物对应、区别或缺少的证据。
   不需要知道地点名称；没找到相似处不等于有证据证明不同。
   查看两张原图后勾选声明，点击“保存本条”，再点“下一条”。
6. 第一优先级共15条，第二优先级共7条。可以分次完成、先回传部分结果。
   “保存本条”只留在当前页面；关闭前点击“下载进度 JSON”，确认文件已经下载。
7. 下次打开相同页面，先“恢复此前下载的 JSON”，再选择本地原图继续。
   恢复会替换页面中的已保存记录，先下载当前进度。未修改的记录保留原复核人和时间。
8. 将下载的 JSON 交给负责人，注明“22条原图复核”，由负责人转交开发代理。
   不需要传原图、手工整理 CSV、写测试日志或重做旧代码评审。

如果无法打开页面、核对报错或按钮无法操作，请直接回复“浏览器名称＋出错步骤＋提示”。
可以附截图。开发代理处理技术问题，不要求组员自行装环境。

## 人的工作与工具的工作

人负责看原图并说明图像依据。判断标准见[场景复核说明](scene-review.md#判断标准)。
清单排序、文件哈希、样本编号、时间、导出恢复和格式检查由工具完成。
页面不显示上轮判断或理由，避免把既有答案当作本轮答案照填。

哈希一致证明当前选中文件与批次记录一致；勾选“已查看”仍是复核人的声明，
不能作为眼动或人工身份认证。回传格式校验也不证明图像判断正确。
新记录使用独立类型 `scene-followup-decisions`，绑定跟进清单、原提交文件和审计批次。
它不能直接代入原来的 `check-groups`，必须先核对与旧判断的差异，再记录人工确认的修订。
不会自动覆盖 Faith 的111条记录、修改划分或放行训练。

## 开发代理生成与接收

这些命令仅处理已存在的 JSON，不读取官方图像，无需配置数据根目录。
实际批次清单和生成页面只能留在忽略的 `.local/`，交由负责人转交，不进公开 Git。
每次生成使用新文件名，已有页面不会覆盖。

```bash
.conda/uav-seg-next/bin/python -m uavseg.followup \
  --request .local/faith-followup-20260914/v3/request.json \
  --output .local/faith-followup-20260914/v3/本地原图复核-v2.html

.conda/uav-seg-next/bin/python -m uavseg.followup \
  --request .local/faith-followup-20260914/v3/request.json \
  --records .local/原图复核进度.json
```

新增合成测试覆盖无原图生成、批次篡改、重复与未知关系、原图身份不符、恢复失败保留工作、
查看声明、部分导出以及复核人和时间保留。Node 执行实际页面脚本；这不等于真实浏览器
图形测试，当前终端没有可用的图形浏览器，组员设备兼容性仍需通过实际打开结果确认。
